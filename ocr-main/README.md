# OCR Microservice

> **Optical Character Recognition (OCR) & Text Extraction Service**  
> **Technology:** .NET 9 LTS / C# 13  
> **Persistence:** Entity Framework Core 9.0 (PostgreSQL `Npgsql.EntityFrameworkCore.PostgreSQL` / In-Memory Fallback)  
> **Engines:** OCRmyPDF / Tesseract 5 (Safe Process Execution with `ArgumentList` + In-Memory Fallback)  
> **Patterns:** Clean Architecture, Database-per-Service, Claim-Check Storage, Asynchronous Request-Reply, Problem Details (RFC 9457)  
> **Repository:** `ocr/`  

---

## 1. Architecture

The microservice implements a strict **Clean Architecture** structured in concentric layers:

```
src/
├── Ocr.Domain/          # Core Domain Entities (OcrJob, OcrJobResult, OcrJobError, JobStatus)
├── Ocr.Application/     # Application Services & Ports (OcrJobService, IOcrJobRepository, IOcrProcessingEngine, IOcrJobQueue)
├── Ocr.Infrastructure/  # Adapters: EF Core (OcrDbContext), OCRmyPDF Engine, Channels Queue, Workers
├── Ocr.Api/             # Web API (OcrJobsController, Health Endpoints: /health/live, /health/ready)
└── Ocr.Worker/          # Dedicated Scale-Out Background Worker Host
tests/
├── Ocr.UnitTests/       # Unit Tests (EfOcrJobRepositoryTests, BasicOcrProcessingEngineTests)
└── Ocr.IntegrationTests/# Full Lifecycle HTTP Integration Tests (WebApplicationFactory)
```

## 2. HTTP Endpoint Specification

The API adheres to the OpenAPI specification defined in [`contracts/ocr-api.openapi.yaml`](../contracts/ocr-api.openapi.yaml).

The canonical frontend integration uses `/api/v1/documents`, published by Kong
as `/api/ocr/v1/documents`. The `/api/v1/ocr/jobs` routes expose the internal
job-oriented contract and are kept for compatibility and diagnostics.

### 2.1. `POST /api/v1/ocr/jobs`
Creates and enqueues a new OCR processing job using the **Asynchronous Request-Reply** pattern.

- **Content-Type:** `multipart/form-data`
- **Parameters:**

| Field | Type | Required | Description |
|---|---|:---:|---|
| `file` | Binary | Yes | File to process (PDF, PNG, JPEG, TIFF; max 50 MB). |
| `clientReference` | String | No | Opaque client identifier (e.g. document reference from ACL). |
| `language` | String | No | ISO 639-2 code (`eng`, `spa`; default: `eng`). |
| `mode` | String | No | Processing strategy (`skip`, `redo`, `force`; default: `skip`). |

- **Response `202 Accepted`:**
  - **`Location` Header:** `/api/v1/ocr/jobs/{jobId}`
  - **JSON Body:**
```json
{
  "jobId": "694cf227-54d9-412c-be5e-e636265837b1",
  "clientReference": "doc-test-100",
  "status": "processing",
  "createdAt": "2026-10-30T06:20:00.000Z"
}
```

---

### 2.2. `GET /api/v1/ocr/jobs/{jobId}`
Queries the current status of a job and retrieves the extracted text and metadata.

- **Response `200 OK` (Job Completed):**
```json
{
  "jobId": "694cf227-54d9-412c-be5e-e636265837b1",
  "clientReference": "doc-test-100",
  "status": "completed",
  "createdAt": "2026-10-30T06:20:00.000Z",
  "completedAt": "2026-10-30T06:20:02.150Z",
  "result": {
    "text": "UNIVERSIDAD NACIONAL Factura de venta correspondiente al periodo...",
    "pageCount": 2,
    "durationMs": 2150,
    "engineVersion": "OCRmyPDF External Process",
    "hasArchivedPdf": true,
    "archiveDownloadUrl": "/api/v1/ocr/jobs/694cf227-54d9-412c-be5e-e636265837b1/archive",
    "hasThumbnail": true,
    "thumbnailUrl": "/api/v1/ocr/jobs/694cf227-54d9-412c-be5e-e636265837b1/thumbnail"
  },
  "error": null
}
```

- **Response `404 Not Found`:** When `jobId` does not exist.
```json
{
  "error": "Job with ID 00000000-0000-0000-0000-000000000000 not found."
}
```

---

### 2.3. `GET /api/v1/ocr/jobs/{jobId}/archive`
Downloads the searchable PDF/A-2b document generated by OCRmyPDF (`Content-Type: application/pdf`).

### 2.4. `GET /api/v1/ocr/jobs/{jobId}/thumbnail`
Downloads the rasterized first-page thumbnail image (`Content-Type: image/png` or `image/webp`).

### 2.5. Health Check Endpoints
- `GET /health/live`: Liveness probe (`{"status":"ok"}`).
- `GET /health/ready`: Readiness probe verifying PostgreSQL connection (`{"status":"ready"}`).
- `GET /api/v1/ocr/health`: OpenAPI standard availability probe (`{"status":"ok"}`).

---

### 2.6. Frontend Contract Endpoints (`/api/v1/documents`)

For the Frontend SPA (React) integration, the microservice exposes dedicated endpoints implementing [`ocr/docs/frontend-ocr-api-contract.md`](docs/frontend-ocr-api-contract.md) with full CORS support and exposed `Location` headers:

| Method & Route | Function | Response |
|---|---|---|
| `POST /api/v1/documents` | Upload document for OCR | `202 Accepted` with `id`, `status: queued`, `Location` header |
| `GET /api/v1/documents` | Paginated documents listing | `200 OK` (`{ items: [...], total, page, pageSize }`) |
| `GET /api/v1/documents/{id}` | Document details and status | `200 OK` (`id`, `fileName`, `contentType`, `sizeBytes`, `status`, `pageCount`, `error`) |
| `GET /api/v1/documents/{id}/text` | Extracted text and metadata | `200 OK` (`documentId`, `text`, `pageCount`, `durationMs`, `engineVersion`) |
| `GET /api/v1/documents/{id}/original` | Download original binary file | Binary stream (`Content-Type` matching original document) |
| `GET /api/v1/documents/{id}/archive` | Download searchable PDF/A-2b | `200 OK` (`application/pdf`) |
| `DELETE /api/v1/documents/{id}` | Delete document and artifacts | `204 No Content` |

## 3. Database Schema (PostgreSQL `ocr_jobs`)

Managed with versioned EF Core migrations (`src/Ocr.Infrastructure/Migrations`).
Deployments apply pending migrations at startup and never call `EnsureCreated`.
The InMemory provider used by tests skips migration setup.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `job_id` | `uuid` | PK | Unique Job Identifier. |
| `client_reference` | `varchar(128)` | NOT NULL | Opaque correlation token from client. |
| `file_name` | `varchar(256)` | NOT NULL | Original document filename. |
| `content_type` | `varchar(128)` | NOT NULL | MIME content type (e.g. application/pdf). |
| `size_bytes` | `bigint` | NOT NULL | Original file size in bytes. |
| `file_storage_path`| `varchar(1024)`| NULL | Path in shared Claim-Check volume (`/shared`). |
| `language` | `varchar(16)` | NOT NULL | Language code (`eng`, `spa`). |
| `mode` | `varchar(32)` | NOT NULL | OCR Mode (`skip`, `redo`, `force`). |
| `status` | `varchar(32)` | NOT NULL | `Pending`, `Processing`, `Completed`, `Failed`. |
| `created_at` | `timestamptz` | NOT NULL | Job submission timestamp (UTC). |
| `processing_started_at` | `timestamptz` | NULL | Claim timestamp; used to reclaim abandoned jobs. |
| `completed_at` | `timestamptz` | NULL | Job completion timestamp (UTC). |
| `result_text` | `text` | NULL | Extracted full text content. |
| `result_page_count`| `int` | NULL | Number of pages parsed. |
| `result_duration_ms`| `bigint` | NULL | Processing duration in milliseconds. |
| `result_engine_version`| `varchar(128)`| NULL | Engine descriptor string. |
| `result_archived_pdf_path`| `varchar(1024)`| NULL | Searchable PDF/A path in shared storage. |
| `result_thumbnail_path`| `varchar(1024)`| NULL | First-page thumbnail path in shared storage. |
| `error_code` | `varchar(64)` | NULL | Semantic error code on failure. |
| `error_message` | `text` | NULL | Error diagnostics message. |

### Job claiming and recovery

- `TryClaimNextJobAsync` claims the oldest available job in a single
  `UPDATE ... RETURNING` with `FOR UPDATE SKIP LOCKED`, so multiple workers can
  run safely in parallel.
- A job left in `Processing` longer than `Worker:StaleJobTimeoutMinutes`
  (default 30) is claimable again and is also returned to `Pending` by the
  periodic recovery pass.
- On graceful shutdown, an in-flight job returns to `Pending` immediately.

## 4. Practical Invocation Examples

### Recommended: public document contract through Kong

The example below assumes the current local layout, with Paperless on `8000`
and Kong on `8080`. If `KONG_PROXY_PORT` changes, use that port instead.

```bash
# Upload a document. The response contains its id and initial queued status.
curl -i -X POST http://localhost:8080/api/ocr/v1/documents \
  -F "file=@/path/to/invoice.pdf;type=application/pdf"

# Query its current state using the id returned above.
curl http://localhost:8080/api/ocr/v1/documents/694cf227-54d9-412c-be5e-e636265837b1

# Retrieve the extracted text after the document reaches completed.
curl http://localhost:8080/api/ocr/v1/documents/694cf227-54d9-412c-be5e-e636265837b1/text
```

### Internal job contract

### Using `curl`
```bash
# 1. Submit document (Multipart Form)
curl -i -X POST http://localhost:5000/api/v1/ocr/jobs \
  -F "file=@/path/to/invoice.pdf;type=application/pdf" \
  -F "clientReference=DOC-99" \
  -F "language=spa" \
  -F "mode=skip"

# 2. Query result using the returned Job ID
curl -X GET http://localhost:5000/api/v1/ocr/jobs/694cf227-54d9-412c-be5e-e636265837b1
```

### Using Python
```python
import time
import requests

# 1. Submit job
with open("invoice.pdf", "rb") as f:
    res = requests.post(
        "http://localhost:5000/api/v1/ocr/jobs",
        files={"file": ("invoice.pdf", f, "application/pdf")},
        data={"clientReference": "DOC-99", "language": "spa", "mode": "skip"}
    )
    res.raise_for_status()
    job_id = res.json()["jobId"]

# 2. Resilient Polling
poll_url = f"http://localhost:5000/api/v1/ocr/jobs/{job_id}"
for _ in range(30):
    time.sleep(1)
    status_res = requests.get(poll_url).json()
    if status_res["status"] == "completed":
        print("Recognized Text:\n", status_res["result"]["text"])
        break
    elif status_res["status"] == "failed":
        print("Error:", status_res["error"])
        break
```

  - Status filtering and invalid-status validation.

## 6. Docker Deployment

El stack completo (Kong, PostgreSQL, API y worker) vive en
`../infrastructure/docker-compose.yml`. Desde el repositorio `ocr`:

```powershell
Set-Location ..\infrastructure
Copy-Item .env.example .env
# Completar POSTGRES_PASSWORD, INTERNAL_TOKEN y PAPERLESS_API_TOKEN.
.\scripts\start.ps1
```

La API se ejecuta con `Worker:Mode=external`: solo persiste el documento y el
contenedor `ocr-worker` lo procesa. Modos disponibles:

| `Worker:Mode` | Comportamiento |
|---|---|
| `embedded` (default local) | La API ejecuta el worker en el mismo proceso. |
| `external` | La API solo encola en base de datos; procesa `Ocr.Worker`. |

Un valor desconocido detiene el arranque con un error explícito. El worker no
expone HTTP: su salud se verifica con el latido
`/tmp/ocr-worker-heartbeat`, actualizado cada 10 segundos.

Para desarrollo sin contenedores:

```bash
dotnet run --project src/Ocr.Api
dotnet run --project src/Ocr.Worker
```

En local, si no se configura una cadena de conexión, se usa el proveedor
InMemory. Los despliegues con PostgreSQL aplican migraciones EF al arrancar.
